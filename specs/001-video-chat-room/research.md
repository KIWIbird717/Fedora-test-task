## Identified conflicts (not ignored)

### CFL-001 — Empty Nx workspace vs constitution layout

**Conflict**: Constitution Principle I requires `apps/web`, `apps/api`, tagged libraries, and module-boundary lint. The repo is an Nx stub.

**Resolution**: Treat the workspace as greenfield. The implementation plan creates that layout. No existing source conventions to reuse beyond pnpm + Nx 23.2.1 + the current `.gitignore`.

### CFL-002 — `pnpm-workspace.yaml` cannot host apps/libs yet

**Conflict**: Workspace packages cannot be linked until `packages:` is defined.

**Resolution**: Add `packages: ['apps/*', 'libs/**']` (or equivalent) during workspace foundation. Keep `allowBuilds.nx`.

### CFL-003 — Root package name

**Conflict**: `"name": "Fedora Meetings"` is not a legal npm/pnpm package name.

**Resolution**: Rename the root package to `fedora-meetings`. Use `@fedora-meetings/*` for workspace projects. Do not change the product/UI name.

### CFL-004 — Spec Kit feature id vs git branch

**Conflict**: `setup-plan.sh` reports `BRANCH=001-video-chat-room` from `.specify/feature.json`, while git is on `main`.

**Resolution**: Planning artifacts live under `specs/001-video-chat-room/`. Git remains on `main` unless a later command creates a branch. This plan does not create a branch.

### CFL-005 — Two TDD output paths

**Conflict**: `docs/prd-design.mdc` wants `/prds/video-chat-room/design-video-chat-room.md`. Spec Kit and the constitution’s planning workflow produce `specs/001-video-chat-room/plan.md` plus research/data-model/contracts/quickstart.

**Resolution**: **`plan.md` and its Phase 0/1 artifacts are the approved TDD.** Do not duplicate a second design tree under `prds/` (two sources of truth would drift). `prd-design.mdc`’s 14 sections are covered by this artifact set (see mapping in `plan.md`).

### CFL-006 — Constitution fixed stack vs this planning request

**Conflict**: Constitution “Fixed stack” lists Nx, pnpm, TypeScript, NestJS, Socket.IO, Zod, OpenAPI, Scalar, React, Vite, TanStack Router/Query, Socket.IO client, `openapi-typescript`, Tailwind, FSD. It does **not** name Docker, shadcn/ui, or Lucide. Deviating from the fixed stack normally needs a constitution amendment.

**Resolution** (justified, not silent):

- **Docker / Compose** are deployment/development infrastructure only. They do not add product architecture, persistence, or services. Principle XII still forbids extra infra (Redis, DB, TURN, brokers).
- **shadcn/ui** is Tailwind-styled source components (not CSS-in-JS, not a second design system). Compatible with Principles XIII–XV.
- **Lucide React** is the single icon library, required for icon-only accessible controls. No second icon set.

A constitution MINOR amendment listing these as allowed tooling is recommended later; it is not required to finish this plan because the user explicitly mandated them for the TDD and they do not contradict MUST rules.

### CFL-007 — PRD “JavaScript (ES6+)” vs TypeScript strict

**Conflict**: PRD §7 / spec C-001 names JavaScript. Constitution and this request require TypeScript strict.

**Resolution**: TypeScript is the source language; emitted runtime is JavaScript. This satisfies the assignment stack without weakening types.

### CFL-008 — Participant id: socket id vs UUID

**Conflict**: Spec C-006 allows “socket id or UUID”. Constitution XI forbids leaking infrastructure identifiers to clients.

**Resolution**: Domain `ParticipantId` is a UUID generated by the domain. The Socket.IO adapter keeps a private `socketId → participantId` map. Clients never see socket ids.

### CFL-009 — POST /rooms vs empty-room leak

**Conflict**: An HTTP “create room” that inserts a 0-participant room would live forever (FR-009 retains a room only while occupied) and would exhaust FR-041.

**Resolution**: `POST /api/rooms` **mints a unique unused id** and does not insert a room. The room aggregate is created on the first successful `room:join`. Ceiling is enforced at that insert (authoritative) and may be pre-checked on POST for UX.

## Decisions

### 1. Workspace shape

- **Decision**: Package-based Nx 23 workspace with pnpm. Apps and libs each have their own `package.json`. Libraries are **non-buildable** (source consumed by app bundlers). Apps are buildable.
- **Rationale**: Matches installed Nx 23.2.1 and pnpm; non-buildable libs avoid extra compile graphs (Principle XII).
- **Alternatives considered**: Integrated repo without per-project `package.json` (worse Docker prune / pnpm linking). Buildable libs (unnecessary cache complexity).

### 2. Nx plugins (to add during implementation, not now)

- **Decision**: `@nx/js`, `@nx/eslint`, `@nx/vite`, `@nx/react`, `@nx/nest`, `@nx/node`, `@nx/playwright`, `@nx/docker`, `@nx/vitest` (or the Nx 23 equivalents inferred by `nx add`).
- **Rationale**: Generators establish apps; `@nx/docker` infers `docker:build` / `docker:run` from Dockerfiles; Vitest is the single unit/integration runner.
- **Alternatives considered**: Jest for Nest + Vitest for Vite — rejected by constitution (“two libraries solving the same problem MUST NOT coexist”). Webpack — rejected; Vite is mandated.

### 3. Node and language

- **Decision**: Node.js 22 LTS. TypeScript 5.x with `strict: true`. ESM. No `any`, no non-null assertions without a why-comment.
- **Rationale**: Current LTS; NestJS and Vite support it; constitution Principle X.
- **Alternatives considered**: Node 20 (acceptable fallback if a plugin lags). CommonJS (fights Scalar ESM and root `"type": "module"`).

### 4. Backend framework mapping

- **Decision**: NestJS (Express adapter) + `@nestjs/websockets` + `@nestjs/platform-socket.io`. Socket.IO 4.x.
- **Rationale**: Constitution stack. Express is Nest’s default and works with `@scalar/nestjs-api-reference` without Fastify’s `withFastify` flag.
- **Alternatives considered**: Fastify adapter (Scalar needs extra flags; no product benefit). Raw Socket.IO without Nest gateways (would leak transport into ad-hoc code).

### 5. Validation and OpenAPI

- **Decision**: Zod schemas live only at boundaries (HTTP DTOs, Socket.IO payloads, env config). OpenAPI 3.1 is generated from those HTTP Zod schemas (or from Nest Swagger decorators that wrap the same Zod models — one source of truth). Scalar serves `/api/docs`. Frontend types via `openapi-typescript` from the committed OpenAPI document. Socket.IO names/payloads live in `libs/contracts/realtime` as TypeScript types + Zod, **not** in OpenAPI.
- **Rationale**: Principles VI–VII. Socket.IO is not HTTP; stuffing it into OpenAPI creates fake REST.
- **Alternatives considered**: Hand-written DTO classes + duplicated frontend types (forbidden). AsyncAPI for sockets (extra stack, not required).

### 6. Hexagonal library split

- **Decision**: See `plan.md` project structure. Domain and application are Nest-free libraries. In-memory repository is the only outbound adapter. HTTP controllers and Socket.IO gateways live in `apps/api` as thin inbound adapters (composition), not as extra presentation libraries.
- **Rationale**: Constitution I–V. Extra `presentation-*` libraries would be ceremony for a single API app (Principle XII). Controllers/gateways are not reused.
- **Alternatives considered**: Presentation as libraries (more Nx projects, no reuse). All backend code in `apps/api` (violates Principle I).

### 7. In-memory atomic join

- **Decision**: `RoomStore.tryJoin(...)` performs existence/create, ceiling, and 4-participant checks **without `await` between check and mutate**. Node’s single thread is not enough once a use case awaits. Leave/delete-last-participant is the same synchronous critical section.
- **Rationale**: FR-007, FR-009, FR-041, constitution VIII.
- **Alternatives considered**: Mutex library (unnecessary on a single-thread store if the critical section is sync). Database transactions (forbidden).

### 8. Room id format

- **Decision**: URL-safe `nanoid` of 12 characters, alphabet `A-Za-z0-9_-`, validated by `^[A-Za-z0-9_-]{8,32}$` (accept invite ids in that range so a minted 12-char id and a pasted valid id both work). Retry mint on collision with an **active** room.
- **Rationale**: Opaque invite credential (A-001) without implying security (FR-006). Short enough to share. Collision with an active room would join that room — retrying on mint avoids accidental merge of “create” into an existing call.
- **Alternatives considered**: UUID in the URL (ugly, still guessable). Cryptographically huge ids (false sense of access control).

### 9. Concurrent room ceiling default

- **Decision**: `ROOM_CEILING` env, default **50**, integer ≥ 1, validated at startup. Configurable; not a product constant (A-012).
- **Rationale**: Bounds memory (NFR-006) for a demo-scale unauthenticated service. Existing rooms never evicted by the ceiling.
- **Alternatives considered**: Unbounded (violates clarification). Per-IP rate limit (explicitly not required).

### 10. HTTP vs realtime responsibilities

- **Decision**: HTTP: health, mint room id, OpenAPI, Scalar. Socket.IO: join/leave, chat, media state, signaling, live roster/system events. WebRTC media never goes through the server.
- **Rationale**: Matches spec C-002/C-003 and constitution VIII.
- **Alternatives considered**: REST for chat (not real-time). Signaling over HTTP polling (rejected by PRD).

### 11. Socket.IO acknowledgement vs push

- **Decision**: Command/response uses Socket.IO **acks** (`room:join`, `chat:send`, `room:leave`, `media:state`). Broadcasts use server push events. Client sets `reconnection: false`.
- **Rationale**: Join/chat need a correlated success/error (room full, validation, rate limit). FR-031/FR-035 forbid automatic reconnect.
- **Alternatives considered**: Default Socket.IO reconnection (violates spec). Only fire-and-forget events (harder error UX).

### 12. WebRTC mesh

- **Decision**: One `RTCPeerConnection` per remote participant (max 3). Existing members **create offers** to a newly joined participant. Track changes use `replaceTrack` / add+renegotiate owned by the WebRTC library, not by React. ICE servers: Google STUN only, from config (`stun:stun.l.google.com:19302` and `stun:stun1.l.google.com:19302`). No TURN. Failed/disconnected ICE for a pair → per-tile error (FR-034), rest of the room continues.
- **Rationale**: Spec C-002/C-004, FR-034, constitution VIII.
- **Alternatives considered**: SFU/LiveKit (explicitly rejected by PRD). Perfect-negotiation-only glare handling as the sole join rule (more complex; offer-from-existing is enough for join). Client libraries like `simple-peer` (hides lifecycle we must own).

### 13. Frontend state

- **Decision**: TanStack Router for routes. TanStack Query **only** for HTTP (`POST /api/rooms`, optional health). Realtime + WebRTC state via a feature-scoped store (`useSyncExternalStore`) owned by `features/meeting-session`. No Zustand/Redux. No `localStorage`.
- **Rationale**: Constitution IX, NFR-005.
- **Alternatives considered**: Zustand (forbidden unless TDD requires it — this TDD does not). Pushing socket events into Query cache (forbidden).

### 14. FSD vs Nx libraries

- **Decision**: FSD layers `app` / `pages` / `widgets` / `features` / `entities` live **inside** `apps/web`. Extracted Nx libs only for: UI kit, media, WebRTC, realtime client, and shared contracts.
- **Rationale**: One frontend app; extracting every slice would be mechanical libraries (Principle I: “never generated mechanically”). WebRTC/media/realtime **must** be libraries so UI cannot import `RTCPeerConnection` or Socket.IO internals (enforced by ESLint).
- **Alternatives considered**: One lib per FSD slice (over-structure). All WebRTC in components (forbidden).

### 15. UI kit

- **Decision**: shadcn/ui (source components in `libs/web/ui`), Tailwind CSS v4 if the Nx/Vite/shadcn toolchain supports it, otherwise Tailwind v3 — **one** Tailwind major. Lucide React only. Semantic CSS variables for light theme; dark-class hooks allowed but **no dark theme shipped**. Font: Inter via `@fontsource-variable/inter` (self-hosted, no runtime font CDN). `cn` = `clsx` + `tailwind-merge`. CVA for primitive variants.
- **Rationale**: User-mandated UI system; constitution XIII–XVI; no CSS-in-JS; no emoji-as-icons.
- **Alternatives considered**: Headless-only + custom CSS (reinvents shadcn). Multiple icon packs (forbidden). CSS Modules (forbidden unless Tailwind cannot solve the problem).

### 16. Testing

- **Decision**: Vitest for unit and Nest integration tests. Playwright for E2E in `apps/web-e2e`. Playwright launch flags: fake media stream / fake UI for camera permissions where the scenario needs it. No coverage-only tests. No arbitrary timeouts; wait on UI/socket events.
- **Rationale**: Constitution testing strategy; deterministic E2E.
- **Alternatives considered**: Cypress (second E2E stack). Jest (second unit runner).

### 17. Docker

- **Decision**: Multi-stage Dockerfiles at `apps/api/Dockerfile` and `apps/web/Dockerfile`, built from repo root. Compose at repo root runs `web` + `api` on a user-defined bridge network. Nginx in the web image reverse-proxies `/api` and `/socket.io` to `api`, so the browser uses **same-origin** URLs. No volume for app state. No DB/Redis/TURN containers. `@nx/docker` for project `docker:build` / `docker:run`. Compose remains the **one-command** full stack. Non-root users. `.dockerignore` at repo root (and per-app if needed).
- **Rationale**: User Docker requirements; Nx 23 `@nx/docker` infers targets from Dockerfiles; same-origin avoids baking Docker DNS names into the SPA; media stays P2P.
- **Alternatives considered**: Vite preview instead of Nginx (worse static serving / websocket proxy). Host network mode (implies media goes through Docker; misleading). Build-arg API URL `http://api:3000` (broken in the browser).

### 18. Development vs production containers

- **Decision**: Compose file is **production-like local deployment** (built images). Local iteration uses `pnpm nx serve api` and `pnpm nx serve web` with a Vite proxy to the API. Do not add a second Compose “dev stack” with bind mounts unless later needed — extra infra.
- **Rationale**: Principle XII; user asked for one convenient Compose command plus separate serve commands.
- **Alternatives considered**: Hot-reload Compose (more moving parts, not required).

### 19. Environment variables

- **Decision**: All environment-specific values via env vars, Zod-validated at API startup. Frontend runtime uses relative URLs in Docker; Vite `envDir` for local `VITE_*` only if proxy is not used. `.env.example` documents every variable. No secrets exist in this product; do not invent API keys.
- **Rationale**: Constitution VI; user Docker rules; NFR-005/C-005.
- **Alternatives considered**: Hardcoded ports/hosts (forbidden). Committing `.env` (gitignored).

### 20. Error model

- **Decision**: Named error classes per layer, mapped at adapters to `{ code, message }` (HTTP body or socket ack). User-visible `message` is Russian and matches spec copy. `code` is a stable English enum for clients. No stack traces to clients.
- **Rationale**: Constitution XI, SC-010.
- **Alternatives considered**: Bare `Error` + string matching (forbidden). HTTP-only errors for socket flows (wrong transport).
